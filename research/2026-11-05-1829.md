## Ringkasan riset

1. Wandr — Mobile Game UI Design: Thumbs, Sessions and Constraints:
   jempol bukan kursor (jangkauan busur, tidak presisi, menutupi yang
   disentuh); target sentuh harus BESAR *dan* BERJARAK — "the spacing
   half gets ignored... a target that meets the minimum size but sits
   flush against another target is still a mis-tap generator"; umpan
   balik harus muncul di atas/di samping titik sentuh, bukan di
   bawah jari; layar HP menuntut pengurangan (fewer things on screen);
   uji di HP terjelek yang didukung, di luar ruangan, bukan emulator.
   Sumber: https://www.wandr.studio/blog/mobile-game-ui-design
2. Cursa — UI Scaling for Mobile Games: Layout Systems and Readability:
   letak dari hubungan (anchor/margin/stack), bukan koordinat absolut;
   teks sekunder jangan di bawah 12-13px; teks di atas gambar butuh
   scrim/panel semi-opak, bayangan saja tidak cukup; target sentuh
   minimal 44-48px, jarak antar target 8-12px; elemen interaktif
   jangan menempel tepi layar (inset nyaman, hati-hati swipe area
   pojok bawah); uji teks panjang (+30-50%) supaya tidak terpotong.
   Sumber: https://cursa.app/en/page/ui-scaling-for-mobile-games-layout-systems-and-readability
3. h-idris — Mobile game UI design: thumb zones and safe areas:
   peta jempol (zona nyaman = sepertiga bawah), layar bukan
   persegi penuh — notch, sudut membulat, dan gesture bar memakan
   tepi; aturan praktis: latar full-bleed, semua elemen interaktif
   dan terbaca di dalam wadah safe-area bermargin sendiri.
   Sumber: https://h-idris.com/blog/mobile-game-ui-design.html
4. Supagames — Mobile-first layout for JavaScript browser games:
   cadangkan ruang untuk kontrol SEBELUM kamera/HUD final (gerakan
   kiri, aksi kanan, HUD penting atas); `bottom:
   env(safe-area-inset-bottom, 0)` + padding; wrapper kontrol
   `pointer-events: none` supaya area kosong tembus ke game;
   hit target boleh lebih besar dari ikon yang terlihat.
   Sumber: https://supagamesai.com/learn/mobile-first-game-layout.html
5. Egmatic — Mobile Game Touch Controls: Design for Thumbs, Not Mice:
   studi Hoober: 49% main satu tangan, ~3/4 sentuhan adalah sentuhan
   jempol; lantai 48dp untuk aksi utama; "a miss should land on
   empty space, not on the neighboring action".
   Sumber: https://egmatic.com/blog/mobile-game-touch-controls-design-for-thumbs

Fakta vs opini: fakta dari sumber — jangkauan jempol busur bawah,
target 44-48px + jarak 8-12px, safe-area-inset, teks sekunder
min 12-13px, scrim di atas gambar, umpan balik di luar titik
sentuh; opini sendiri — di Nusantara label hewan TIDAK ikut antrean
rapikan (terbukti di kode `Map3D.tsx`: label hewan diposisikan
langsung, hanya label warga yang lewat `rapikanLabelBertumpuk`),
jadi tumpukan di pusat kampung — tempat hewan jinak + warga
berkerumun — bukan kegagalan fungsi rapikannya, melainkan antrean
yang tidak lengkap.

## Ide konkret

### 1. Label hewan ikut antrean rapikan yang sama (TIDAK dibangun run ini — observasi mengubah diagnosis)
Masalah pemain: r42 merapikan label warga, tapi observasi live
16:29 tetap melihat tumpukan label di tengah kampung. Dugaan awal:
label hewan tidak ikut antrean. Observasi 18:29 membuktikan
tumpukan itu label WARGA (5 nama: Renata, Go Younjung, Budi, reja
auditore, ribran gakabuming) — hewan hampir semua di luar kamera.
Akar sebenarnya: pil label ~19px tingginya, ambang 18px + langkah
20px hanya memberi celah 1-2px. Yang dibangun run ini: jarak
rapikan 18/20px -> 28px (pil ~19px + celah ~9px). Label hewan
tetap di luar antrean — dicatat sebagai Ide 33 di IDE-FITUR.md,
bukan dibangun sekarang karena bukan penyebab yang teramati.
Cara kerja (bila nanti dibangun): satu antrean gabungan (warga +
hewan) lewat `rapikanLabelBertumpuk`; transform label hewan
diterapkan setelah loop hewan, bukan langsung di dalam loop.
Dampak sedang, usaha kecil.

### 2. Safe-area inset untuk klaster kontrol bawah (TIDAK dibangun run ini, backlog)
Masalah: laporan observasi r43 — joystick analog kiri-bawah
terlihat terpotong tepi kiri viewport 1919x998, padahal CSS-nya
`left: 12px`; penyebab pastinya belum terkonfirmasi visual.
Observasi 18:29 TIDAK mengulanginya (analog utuh dengan margin
jelas dari tepi kiri) — jadi TIDAK ada yang diubah run ini.
Sumber (h-idris, Supagames) menyarankan
`env(safe-area-inset-*)` + margin wadah sendiri, bukan angka tetap.
Cara kerja: klaster bawah memakai inset safe-area + audit visual
ulang sebelum mengubah angka apa pun; jangan menebak penyebab
dari CSS saja. Dampak sedang, usaha kecil-sedang (butuh bukti
visual dulu). Masuk backlog sebagai Ide 34.

### 3. Label hemat saat kerumun: hewan jinak disembunyikan saat kamera jauh (TIDAK dibangun run ini)
Masalah: 27+ label sekaligus di layar = kebisingan visual
(Wandr: kurangi, bukan padatkan; Cursa: prioritas tampil).
Cara kerja: saat kamera jauh, tampilkan hanya label warga +
hewan yang sedang diburu/terluka; label hewan jinak muncul saat
kamera mendekat. Display-only. Dampak sedang, usaha kecil-sedang.
Menunggu bukti ide 1 belum cukup dulu.

## Tidak direkomendasikan
- Memperkecil font label di bawah 11px supaya muat (melawan
  keterbacaan: Cursa min 12-13px untuk label sekunder; label
  Nusantara sudah 11px — mengecilkan lagi = tidak terbaca di HP).
- Memindah semua kontrol ke atas layar (melawan jangkauan jempol;
  Wandr: aksi utama di sepertiga bawah, atas hanya untuk status).
- Tur interaktif multi-langkah di atas kanvas 3D (rapuh; sudah
  dicatat tidak direkomendasikan di riset-riset sebelumnya).
- Menebak penyebab analog terpotong lalu mengubah angka CSS tanpa
  bukti visual (observasi run ini harus mengonfirmasi dulu).
